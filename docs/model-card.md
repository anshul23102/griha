# Model card: Griha risk and valuation models

Everything here is measured on **synthetic data generated by this project** (`griha/synth.py`). None of it describes how the models would behave on real Indian borrowers. Source: `backend/artifacts/train_metrics.json`, model version `ba3f1a223c13`.

## Intended use
Rank applicants by probability of default and estimate property value to support an underwriter's decision in a demonstration of an underwriting engine. Not for production lending without retraining and validation on the lender's own data.

## Models
| Model | Method | Why |
|---|---|---|
| Probability of default | LightGBM with monotone constraints, isotonic calibration, conformal prediction sets, SHAP explanations | Monotone so that, for example, a higher FOIR can never lower risk; explanations feed the written reasons |
| Property value | Quantile gradient boosting (10th, 50th, 90th percentile) | Gives a range, and the range feeds the valuation rules |
| Document and behaviour anomaly | Isolation forest plus rule checks | Flags statements that do not look like their claimed income |

## Measured results (720 held-out synthetic applicants)
- Ranking (AUC): **0.747**; KS 0.414; Brier 0.058.
- Baselines on the same split: FOIR alone 0.723, bureau score alone 0.577, **plain logistic regression 0.760**.
- **The GBM does not beat logistic regression on this data.** The synthetic default process is close to linear, so there is little for a tree model to find. We keep the GBM for monotonic constraints and SHAP, and we say so rather than quoting only the flattering baseline.
- Calibration: mean predicted default 7.3% against 6.0% observed, so the model is slightly conservative on this data.
- Conformal coverage of the prediction sets: 96.5% (non-default) and 97.7% (default) against a nominal level.
- Property value: median absolute percentage error 6.3%; share within 10% of true value 80.3%; the 80% interval covers 73.9%, which is **below its nominal 80%**, so the property range is slightly too narrow.

## Fairness and drift
- The simulator page shows approval-rate gaps by group when a policy threshold moves. The twelve model inputs (`features.py`) are FOIR, LTV, bureau score, income variability, savings buffer, worst delinquency, enquiries, bounced payments, self-employed flag, age, tenure and loan-to-income. Sex, religion and caste are not inputs. **Age is an input** (it is needed for tenure limits), so age effects should be reviewed before real use.
- A PSI drift monitor compares live applications to the training reference once at least 100 distinct applicants exist.

## Limits
- Synthetic training data, so no claim of real-world accuracy.
- Policy cut-offs are illustrative; the lender's own values were not available.
- A US loan-level validation was run privately; it is unpublished until the data provider clears it.
